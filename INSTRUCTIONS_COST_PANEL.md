## Goal
After a countermeasure is selected (manually, or by the Intelligent Shift Advisor) and checked, the CEO must see **extremely clearly what the improvement costs and what it brings back**. Every amount must come from the rate card (`rate_card.csv`) or a clearly marked assumption.

The panel has three layers:
1. **One headline sentence**, generated by code (not by the LLM).
2. **Two tables:** "What you pay" and "What you get", each line with its formula and amount. Below them, two indicators: **cost per rescued order** (compared with the €90 penalty) and **payback**.
3. **A profit bridge chart:** a waterfall from the "As is" profit to the "With countermeasure" profit.

**Scope:** short term only, i.e. the chosen number of shifts with 10 runs, as the check does today.
A **long-term view** (one year, background worker) is a **later, separate step: do not build it now**. Design the breakdown function so it can be reused for it unchanged: it only needs two sets of economics.

## Step 2: A pure breakdown function
Create `src/economics/breakdown.js`:

```js
/**
 * costBreakdown({ without, with: withRuns, rate, shifts, label })
 *   without / withRuns: arrays of per-run records { econ, shipped, shippedOnTime, ordered, released, goodParts, fgStart, fgEnd }
 *                        (same seeds, same order: paired). One-element arrays = a single run (side-by-side view).
 * returns {
 *   basis: { runs, shifts },
 *   pay:   [ { key, label, formula, amount, assumption? } ],   // cost lines, positive = extra cost
 *   get:   [ { key, label, formula, amount } ],                // benefit lines, positive = gain
 *   totals: { costOfImprovement, benefits, profitChangeOfficial, unsoldStockValue, profitChangeConservative },
 *   investment: { cash, items: [ { label, formula, amount } ], chargedThisPeriod },
 *   rescuedOrders,             // mean Δ shippedOnTime
 *   costPerRescuedOrder,       // costOfImprovement / rescuedOrders (null if rescuedOrders <= 0)
 *   penaltyPerLateOrder,       // rate.lost_sales_penalty (90)
 *   payback: { shifts, years, withinLife } | null,   // null when there is no investment
 *   headline,                  // plain sentence, built from the numbers above
 * }
 */
```

**All amounts are means over the runs of the paired difference (with − without).**

| Line | Table | Amount (mean Δ) | Formula text shown to the CEO |
|---|---|---|---|
| `investmentShare` | pay | Δ`amortised` | "€{cash} ÷ 1,920 shifts × {shifts} shifts" |
| `overtime` | pay | Δ`overtimeCost` | "{hours} h × €{rate}/h *(assumption)*". Get the rate from `overtimeRatePerHour(config, rate)`. |
| `machineHours` | pay | Δ`machineCost` | e.g. "second M3: €90/h × 8 h × {shifts} shifts" |
| `material` | pay | Δ`materialCost` | "{Δreleased} extra parts × €38" |
| `storage` | pay | Δ(`holdingWip` + `holdingFg` + `holdingRaw`) | "parts in the line €0.30/h, finished sets €0.50/h" |
| `startStock` | pay | Δ`startValue` | only if a countermeasure sets starting stock (none does today; keep the line generic) |
| `penaltiesAvoided` | get | −Δ`lostSales` | "{rescued} sets no longer late × €90" |
| `revenue` | get | Δ`revenue` | "{Δshipped} sets × €180" |
| `endStockValue` | get | Δ`endValue` | "finished sets left at the end × €103" |

**Rules:**
- **Show negative amounts with their sign** (a cost that goes *down* is a saving). Hide a line only when its amount is exactly 0 in every run.
- **Identity (must hold, and is tested):** `Σget − Σpay = Δprofit (official)` = the mean of `profit(with) − profit(without)`, within €0.01.
- `unsoldStockValue` = €103 × mean(max(0, extra build)), where extra build = (fgEnd − fgStart)with − (fgEnd − fgStart)without, per run. This matches `conservative()` in `src/scenarios/sweep.js`; reuse it or extract it to a shared helper.
- `profitChangeConservative` = `profitChangeOfficial − unsoldStockValue`. It must equal `change.profitConservative.mean` from the evaluator.
- `costOfImprovement` = Σ`pay`.
- **Investment cash** (full amount, not amortised) comes from the "with" run's `econ.oneTime.items`. Each non-zero item becomes a line with its formula from `oneTime.counts`, e.g.:
  - "2 min × €30,000 × 1 machine" (or "× 2 machines" when the faster M3 is combined with a second M3);
  - "€95,000 per extra machine".
- **Payback** (only if `cash > 0`):
  - operating gain per shift = (`profitChangeConservative` + Δ`amortised`) ÷ `shifts`, i.e. the gain before the investment share;
  - `shifts` = cash ÷ gain, rounded up; `years` = shifts ÷ 240;
  - `withinLife` = shifts ≤ 1,920;
  - if gain ≤ 0, `payback = { shifts: null, years: null, withinLife: false }`, shown as "never at these numbers".
- **Headline** (template, choose the variant by the numbers):
  - "To deliver **{rescued}** more sets on time over {shifts} shifts, you pay **€{costOfImprovement}** and avoid **€{penaltiesAvoided}** in late-delivery penalties. **No upfront investment** is needed."
  - With an investment: "… and it needs **€{cash} upfront**, paid back after about {payback.shifts} shifts (≈ {years} years)", or "… which does **not** pay back at these numbers."
  - If `unsoldStockValue > 0`, add: "It also builds {n} sets nobody ordered (worth €{unsoldStockValue} on paper, not counted as profit here)."
  - If `rescuedOrders ≤ 0`: "This does not deliver more orders on time."
- **Rounding:** round only for display (whole euros, sets to 1 decimal place when averaged). Keep raw numbers in the JSON.

## Step 3: Wire it into the results
1. **Proposal card (the reliable numbers).**
   - `evaluateSelection` (`src/countermeasures/evaluate.js`) returns a new field `costs: costBreakdown({ without: base.rows, with: variant.rows, rate, shifts, label })`.
   - `POST /api/countermeasures/test` and `POST /api/advisor/improve` pass it through to the client.
   - The panel is labelled: "Averages of {runs} runs over {shifts} shifts."
2. **Side-by-side comparison (this run).**
   - In `GET /api/compare/results`, compute `computeEconomics` for engines A and B: `liveResult(engine)` + the engine config, as `buildRunSummary` already does internally. Add `costs: costBreakdown({ without: [recA], with: [recB], ... })` with one-element arrays.
   - Label it "This run (one run, same random draws)" and add the note "The averages in the proposal card above are more reliable."
3. **LLM (optional, small).** Add `costs.headline` and the `pay` / `get` lines to the FACTS that the advisor receives for its `reason`, so its wording matches the panel. The LLM still invents no numbers.

## Step 4: The panel (UI)
Place a **"Cost of the improvement"** block inside the proposal card, under the simulation check and verdict. Place a second one under the side-by-side before → after tiles. Use **one render function for both**, e.g. `renderCostPanel(container, costs, { basisLabel })`.

1. **Headline:** large, plain text, on a light background strip. Bold the euro amounts.
2. **Two tables next to each other** (stacked below 900 px):
   - **What you pay**: columns *Item · How it's calculated · Amount*, with a **Total cost of the improvement** row.
   - **What you get**: same columns, with a **Net effect on profit** row = official Δprofit.
   - Under it, a muted line: "Of which {n} sets nobody ordered, worth €{unsoldStockValue} on paper → **conservative net effect €{profitChangeConservative}**". Only when `unsoldStockValue > 0`.
   - Amounts are right-aligned, with a thousands separator and the € sign; costs in red, gains in green. Negative costs (savings) show as green "−€…".
   - **Assumption** lines get a small "assumption" tag. Its tooltip names the source: "No rate-card price for overtime: hour rates of all four machines (€270) + 50% premium". The cycle-time and reject-rate investments are tagged "organiser assumption (rate card)".
3. **Investment box** (only when `cash > 0`): "Upfront investment: **€{cash}**", the item lines, then "charged to this period: €{chargedThisPeriod} (spread over 8 years)", then the payback sentence.
4. **Two indicator chips:**
   - "Cost per rescued order: **€{costPerRescuedOrder}** vs **€90** penalty per late order". Green if below 90, amber if above. Tooltip: "A late order costs €90 in penalty; the sale itself is kept."
   - "Payback: **{shifts} shifts (≈ {years} years)**", or "no investment", or "never at these numbers".
5. **Profit bridge chart (inline SVG):**
   - first bar = "As is" profit, last bar = "With countermeasure" profit (both absolute);
   - in between, one floating bar per non-zero line: gains up (green), costs down (red), in the table order;
   - value labels on the bars, the axis in €, readable on the light theme.
   - When `unsoldStockValue > 0`, add a dashed final segment "minus unsold stock" down to the conservative result.
   - Add a text fallback (`<title>` / `aria-label`) listing the bars.
6. **Placeholder comparison table** (from the previous step): leave it as a placeholder. Don't fill it in this step.

## Step 5: Tests (`test/`)

- For `overtime`, `faster-m3`, `second-m3` and the combination `faster-m3 + second-m3`:
  - the identity Σget − Σpay = official Δprofit (±€0.01);

- **Investment cash:**
  - overtime 0;
  - faster M3 (2 min) 60,000;
  - second M3 95,000;

- **Overtime line** = hours × `overtimeRatePerHour` (405 on the default line).

- **Headline:** contains the rescued sets and the cost; mentions the upfront investment exactly when `cash > 0`.
